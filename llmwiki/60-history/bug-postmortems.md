# Bug postmortems

The failure history of this integration, as recorded by the engineers who fixed each
one. Read it before proposing a fix in a nearby area: several entries recurred because
the earlier refutation was never written down.

## How to read this table

- **The Grade column grades the root-cause claim**, not the fix and not the symptom.
- Unless a row names another source, the source is the migration corpus postmortem
  catalogue (§3), distilled from the maintainer's memory files
  `memory/issue-<n>-*.md` — **outside this repo** and not guaranteed to exist.
  That is why the default grade is `asserted-unverified`: the account is contemporaneous
  engineer testimony, not something re-derived here.
- **✔ in the Fix column** means the named symbol was confirmed present (or, where
  stated, confirmed absent) in the tree at `9f6d6e2` — `verified-against-code`. It
  verifies only that the fix is still there; it does not re-verify the root cause.
- `#nnn` are GitHub issues in `joyfulhouse/eg4_web_monitor` unless noted.

## Cross-cutting patterns

Recurrences, not one-offs. Each has bitten more than once.

| Pattern | Instances | Rule |
|---|---|---|
| **Fake-confident zero** — the cloud returns a structurally valid 0 for a field it cannot compute | #490, #497, #514 | Detect by contradiction with a live sibling value; derive or blank, never trust the 0 |
| **Required field on an optional payload** — a partial cloud response raises `ValidationError`, gets swallowed, and blanks a device | #256 (`InverterRuntime`/`BatteryInfo`), #258 (`UserVisitRecord` on login), #353 (`UpdateStatus` enum) | Every cloud live-measurement field Optional; every vendor enum gets an unknown-value fallback |
| **Swallowed failure** — an exception or an all-None result passes as success | #322, #348, #511/#516 | `return_exceptions=True` means nothing propagates; a truthy schema-shaped dict is not reachability |
| **Falsy vs absent** — `0`, `False`, `None` and "key missing" conflated | #261 (`inv if inv else bms`), #511 | Compare against None explicitly in merges and reachability checks |
| **Availability by key-presence** — a dropped key becomes an unavailable entity | #253, #258 beta.18, #261, #479 | Extract-then-null; never gate data by dropping keys |
| **Contradictory staleness heuristics** — independent freshness rules disable each other | #170/#258 | Before adding a staleness rule, check what the existing rules already assume; bound every never-evict rule |
| **Capability gated on the wrong grain** — model string, or a family where the defect splits inside it | #259 (too coarse a string), #490 (family too coarse), #544 (family gate correct) | Gate on family; verify the split before generalising from two observations |
| **Throttle/stamp bugs** — a stamp recording attempt rather than success, or a `0.0` monotonic default | #282, #378/#380 and five more sites found in the 2026-08-02 audit (INT-08) | Stamp only on success; use a `None` sentinel for "never ran" — `time.monotonic()` is host uptime, so `0.0` reads as throttled on every freshly booted host |
| **Write path never delta-tested** — a success-shaped API sending garbage, or writing a wrong-but-writable bit | pylxpweb cloud writes, #476 | A successful write proves format acceptance, not targeting |
